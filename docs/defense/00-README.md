# Hair2Harvest — First Defence Documentation Pack

**Prepared:** 22 November 2026  
**Status:** Working baseline. `TO CONFIRM` means the value must be checked against the final paper, blueprint, or lab record before submission.

---

## 1. Purpose

This pack gives the team one place to maintain the documents, evidence, and answers used for the first defence. It is deliberately split into three layers:

1. **Standards** — how every document must be written, numbered, evidenced, and revised.
2. **Templates** — copy-ready skeletons for the documents the panel will ask for.
3. **Baselines** — the current, code-grounded system design, hardware systemization, and defence Q&A.

It does **not** replace the thesis, blueprint, or lab results. It keeps the defence narrative consistent with what the system actually does.

| `VERIFIED — BLUEPRINT` | Confirmed from the v17 blueprint extraction | Safe to present as design intent |

| `TO CONFIRM` | Not yet verified in the supplied final papers | Say “design assumption, pending final verification” |
| `NOT IMPLEMENTED` | Planned/target state, not in the current build | Never present as completed |
